# ขั้นตอนกู้ข้อมูล Benjamin PMS

เอกสารนี้เขียนจากการซ้อมจริงเมื่อ 26 ส.ค. 2569 ตัวเลขเวลาทั้งหมดวัดได้จริง ไม่ใช่ประมาณ

## สรุปสั้น

| เรื่อง | ผลที่วัดได้ |
|---|---|
| สำรองข้อมูล | ~80 วินาที (ข้อมูล ~10 MB) |
| กู้กลับเข้าฐานข้อมูลเปล่า | ~2 วินาที |
| ข้อมูลที่กู้กลับได้ | ครบทุกตาราง รวมบัญชีผู้ใช้และไฟล์แนบ |

## สิ่งที่ไฟล์สำรองครอบคลุม

ต้องเก็บครบ **3 ไฟล์** ถึงจะกู้ได้:

- `roles.sql` — บัญชีระดับฐานข้อมูล
- `schema.sql` — โครงสร้างตาราง ฟังก์ชัน และกติกาสิทธิ์ (RLS)
- `data.sql` — ข้อมูลทั้งหมด **รวมบัญชีผู้ใช้ (auth) และไฟล์แนบ (storage)**

ยืนยันจากการซ้อม: ลูกค้า 50 · ลูกค้าเป้าหมาย 114 · ใบเสนอราคา 111 · นัดหมาย 57 · ไฟล์ 74 · บันทึกการใช้งาน 40,579 · บัญชีผู้ใช้ 9 — **กลับมาครบทุกรายการ ไม่ขาดแม้แถวเดียว**

## วิธีสำรอง

```bash
bash scripts/backup-db.sh                 # เก็บลง backups/<วันเวลา>/
bash scripts/backup-db.sh D:/backup/pms   # หรือระบุที่เก็บเอง
```

⚠️ **ก่อนรัน ตรวจก่อนเสมอว่าผูกอยู่กับฐานข้อมูลชุดไหน**

```bash
cat supabase/.temp/project-ref
```

- `yhhhcrvhkforwsagojho` = **ของจริง**
- `fxckixlzsfqalqukhuud` = **ชุดทดสอบ**

## วิธีซ้อมกู้ (ไม่แตะของจริง)

```bash
npx supabase start                                   # เปิดฐานข้อมูลในเครื่อง
bash scripts/restore-db-drill.sh backups/<วันเวลา>   # ล้างของในเครื่องแล้วกู้จากไฟล์สำรอง
```

สคริปต์จะพิมพ์จำนวนตาราง บัญชีผู้ใช้ ลูกค้า และใบเสนอราคาที่กู้กลับมาได้ ให้เทียบกับของจริง

## กู้ขึ้นฐานข้อมูลจริง (กรณีเกิดเรื่องจริง)

1. สร้างโปรเจกต์ Supabase ใหม่ แล้วผูกด้วย `npx supabase link --project-ref <รหัสใหม่>`
2. ยิงไฟล์สำรองเข้าไปตามลำดับ **roles → schema → data** (ห้ามสลับลำดับ)
3. เปลี่ยน `NEXT_PUBLIC_SUPABASE_URL` และคีย์ในไฟล์ตั้งค่าของทั้งสองแอปให้ชี้โปรเจกต์ใหม่
4. เข้าเว็บแล้วลองล็อกอิน ออกใบเสนอราคา 1 ใบ เพื่อยืนยันว่าใช้งานได้จริง

## ข้อความเตือน 2 อันที่ขึ้นตอนกู้ — ไม่ใช่ปัญหา

- `permission denied for parameter log_min_messages` — เป็นการตั้งค่าบันทึกล็อกที่ฐานข้อมูลในเครื่องไม่ให้แก้ ไม่เกี่ยวกับข้อมูล
- `duplicate key ... buckets_pkey` — ที่เก็บไฟล์มีอยู่แล้ว ข้ามได้

## กับดักที่เจอจริงตอนซ้อม

- บน Windows (Git Bash) คำสั่ง `docker exec ... -f /tmp/x.sql` จะถูกแปลงพาธเป็นวินโดวส์ แล้ว **ล้มเหลวเงียบ ๆ ทั้งที่ดูเหมือนสำเร็จใน 1 วินาที** — สคริปต์ตั้ง `MSYS_NO_PATHCONV=1` กันไว้แล้ว
- อย่าเชื่อ "เสร็จเร็วผิดปกติ" ให้นับจำนวนแถวเทียบเสมอ
