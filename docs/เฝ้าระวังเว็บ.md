# ตัวเฝ้าระวังเว็บ (แจ้งเตือนเวลาระบบล่ม)

## ตอนนี้มีอะไรแล้ว

- **จุดเช็กสุขภาพ** `/api/health` มีอยู่แล้วทั้งสองแอป — ไม่ได้แค่ตอบว่า "เซิร์ฟเวอร์ยังไม่ตาย"
  แต่**ยิงถามฐานข้อมูลจริง**ด้วย ถ้าฐานข้อมูลล่ม จะตอบว่าไม่ไหว (รหัส 503)
- **ตัวเฝ้าระวังอัตโนมัติ** `.github/workflows/uptime.yml` — ยิงถามทุก 10 นาที
  ถ้าไม่ไหวติดกัน 3 ครั้ง (ห่างกัน 20 วินาที) งานจะตก แล้ว **GitHub ส่งอีเมลแจ้งเจ้าของ repo ทันที**
  ไม่ต้องสมัครบริการเสริม ไม่มีค่าใช้จ่าย
- **เช็กด้วยมือ** `bash scripts/check-health.sh http://localhost:3002 http://localhost:3001`

## ต้องทำอะไรถึงจะเริ่มเฝ้าจริง

ตัวเฝ้าระวังยัง "ข้าม" อยู่ เพราะยังไม่มีเว็บใช้งานจริง พอเปิดใช้จริงแล้วให้ตั้งค่า 2 ตัวใน GitHub

**Settings › Secrets and variables › Actions › Variables › New repository variable**

| ชื่อตัวแปร | ค่า |
|---|---|
| `HQ_HEALTH_URL` | `https://<เว็บสำนักงานใหญ่จริง>/api/health` |
| `DEALER_HEALTH_URL` | `https://<เว็บตัวแทนจริง>/api/health` |

ตั้งเสร็จแล้วกด **Actions › เฝ้าระวังเว็บ › Run workflow** เพื่อลองยิงดูทันทีว่าเตือนถูกต้อง

## ⚠️ ห้ามใส่เว็บตัวอย่าง (demo)

เว็บตัวอย่างตั้งใจไม่ต่อฐานข้อมูล (ตามที่ตกลงไว้) จุดเช็กสุขภาพจึงตอบว่า "ไม่ไหว" เป็นปกติ
ถ้าเอาไปใส่ในตัวเฝ้าระวัง จะเตือนผิดทุก 10 นาทีจนไม่มีใครอ่านอีกเลย
