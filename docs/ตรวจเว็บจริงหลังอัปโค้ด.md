# ตรวจเว็บใช้งานจริงหลังอัปโค้ดขึ้น

## ทำไมต้องมี

จุดเช็กสุขภาพ (`/api/health`) ตอบว่า "ปกติ" ได้ทั้งที่ผู้ใช้เปิดหน้าแล้วเห็นจอแดง
**26 ส.ค. 69** แดชบอร์ดสำนักงานใหญ่พังทั้งหน้าเมื่อเลือกช่วง "วันนี้" — ตัวเฝ้าระวังเดิมไม่เห็นอะไรผิดเลย
รู้เรื่องเพราะผู้ใช้ทักมาเอง

ชุดนี้เปิดหน้าจริงบนเว็บจริงด้วยเบราว์เซอร์จริง แล้วดูสิ่งที่ผู้ใช้เห็น:

- ไม่มีจอ "เกิดข้อผิดพลาดในหน้านี้"
- ไม่ถูกเด้งกลับหน้าเข้าสู่ระบบ
- หน้ามีเนื้อหาจริง ไม่ใช่จอเปล่า
- ไม่มี error ที่คอนโซลเบราว์เซอร์

ไล่ครบทุกหน้า **× ทุกช่วงเวลา** (วันนี้ · 7 วันล่าสุด · เดือนนี้ · ปีนี้) เพราะบั๊กจริงซ่อนอยู่ในช่วงเวลาเดียว

> ⚠️ ชุดนี้ **อ่านอย่างเดียว** ไม่สร้าง ไม่แก้ ไม่ลบข้อมูลบนเว็บจริง

## รันในเครื่อง

สร้าง `tests/.env.prod` (ไฟล์นี้ถูก git กันไว้แล้ว ไม่หลุดขึ้น repo):

```
PROD_ADMIN_EMAIL=...
PROD_ADMIN_PASSWORD=...
PROD_DEALER_EMAIL=...
PROD_DEALER_PASSWORD=...
```

แล้วสั่ง:

```
npm run smoke:prod
```

ยังไม่ตั้งบัญชี = ข้ามพร้อมบอกเหตุผล ไม่ล้ม

## ให้ทำงานอัตโนมัติทุกครั้งที่อัปโค้ดขึ้น

ตั้งค่าครั้งเดียวที่ GitHub → **Settings › Secrets and variables › Actions › Secrets**:

| ชื่อ | ค่า |
| --- | --- |
| `PROD_ADMIN_EMAIL` | อีเมลผู้ดูแลสำนักงานใหญ่ |
| `PROD_ADMIN_PASSWORD` | รหัสผ่านของบัญชีนั้น |
| `PROD_DEALER_EMAIL` | อีเมลตัวแทนหนึ่งราย |
| `PROD_DEALER_PASSWORD` | รหัสผ่านของบัญชีนั้น |

จากนั้น `.github/workflows/smoke-prod.yml` จะเด้งทำงานเองทุกครั้งที่ Vercel อัปโค้ดขึ้นสำเร็จ
ถ้าเจอปัญหา งานจะ "ตก" แล้ว GitHub ส่งอีเมลแจ้งเจ้าของ repo ทันที

ย้ายโดเมนเมื่อไหร่ ตั้งตัวแปร `PROD_HQ_URL` / `PROD_DEALER_URL` ทับได้ (Variables) ไม่ต้องแก้ไฟล์

## เกี่ยวข้องกัน

- `.github/workflows/uptime.yml` — เคาะประตูทุก 10 นาที (เว็บยังตอบไหม)
- ชุดนี้ — เปิดหน้าเหมือนผู้ใช้ ทุกครั้งที่อัปโค้ด (ผู้ใช้เห็นอะไร)
- `npm run test:api` — ชุดทดสอบเต็มในเครื่อง **แต่รันโหมดเดียวกับเว็บจริง** (กันบั๊กตั้งแต่ก่อนอัปขึ้น)
