## 1. สรุปสำหรับผู้บริหาร

| หัวข้อ | ผล |
|---|---|

## 2. ทดสอบอะไรบ้าง

### 2.1 แยกตามชนิดของการทดสอบ

| ชนิด | จำนวนข้อ | ทดสอบอะไร |
|---|---|---|
| ใช้งานจริง (func) | 85 | กดปุ่มแล้วข้อมูลลงฐานจริงไหม · เปลี่ยนสถานะแล้วยอดขยับถูกไหม |

| โหลดหนัก (stress) | แยกรัน | 10 ตัวแทนทำงานพร้อมกันเต็มวงจร แล้วข้อมูลต้องไม่ปนกัน |

### 2.2 แยกตามโมดูลของระบบ

ครบทุกโมดูลที่มีในระบบ ทั้งฝั่งตัวแทนจำหน่ายและสำนักงานใหญ่

- **ฝั่งตัวแทน** — แดชบอร์ด · ลูกค้าเป้าหมาย · ใบเสนอราคา (รวมรายการวัสดุ BOQ และภาษี) · ลูกค้า · ปฏิทินนัดหมาย · ไฟล์แนบ · แม่แบบสินค้า · ตั้งค่า · บัญชีเข้าระบบ
- **ฝั่งสำนักงานใหญ่** — แดชบอร์ดทั้งเครือ · ตัวแทนจำหน่าย · ภาพรวมยอดขาย · ลูกค้าเป้าหมายทั้งเครือ · ใบเสนอราคาทั้งเครือ · ลูกค้าทั้งเครือ · แคตตาล็อกแม่แบบ · บันทึกการใช้งาน · ตั้งค่า · ผู้ใช้ HQ

## 3. ความปลอดภัยของข้อมูล

| มาตรการ | สถานะ |
|---|---|
| กฎกันข้อมูลข้ามสาขาที่ระดับฐานข้อมูล (RLS) | **74 ข้อ** — ตัวแทนอ่านได้เฉพาะของสาขาตัวเอง แม้ยิงตรงเข้าฐานก็ไม่ผ่าน |
| รหัสผ่านตัวแทนที่เก็บไว้ | เข้ารหัสแบบ AES-256-GCM กุญแจอยู่ฝั่งสำนักงานใหญ่เท่านั้น |
| การดูรหัสผ่านของตัวเอง | ต้องยืนยันด้วยเลขที่ส่งไปทางอีเมลก่อนทุกครั้ง + บันทึกไว้ในระบบว่าใครเปิดดูเมื่อไหร่ |
| การแก้อีเมล/รหัสผ่านเอง | จำกัด 2 ครั้งตลอดอายุบัญชี ครั้งที่ 3 ต้องให้สำนักงานใหญ่อนุมัติ |
| ด่านจำกัดจำนวนคำขอ | อ่าน/เขียนแยกโควตากัน นับแยกรายบัญชี ปลอมเป็นคนอื่นไม่ได้ |
| กุญแจระดับระบบ | อยู่ในแอปสำนักงานใหญ่ที่เดียว แอปตัวแทนเรียกผ่าน API เท่านั้น |
| บันทึกการใช้งาน | บันทึกทุกการเปลี่ยนแปลงสำคัญ ว่าใคร ทำอะไร เมื่อไหร่ |

**ทดสอบจริงแล้ว**: ลองยิงคำขอเขียนเกินโควตา → ระบบผ่านให้ 300 รายการแล้วปฏิเสธทันที ส่วนงานอ่านยังทำได้ตามปกติ (คนละถัง) · ลองใช้บัญชีสาขา ก. ขอข้อมูลของสาขา ข. → ไม่ได้ข้อมูลกลับมาเลย

## 4. ทดสอบบนเซิร์ฟเวอร์จริง

นอกจากทดสอบในเครื่องแล้ว ยังตรวจบนเว็บใช้งานจริงหลังนำขึ้นทุกครั้ง

- เปิดครบทุกหน้า × ทุกช่วงเวลาของตัวกรอง (วันนี้ / 7 วัน / เดือนนี้ / ปีนี้) — ไม่มีหน้าไหนพัง ไม่มี error ที่คอนโซล
- ทดสอบวงจรบัญชีครบ 16 ข้อบนฐานข้อมูลจริง แล้ว **ลบข้อมูลทดสอบออกหมด** รวมถึงรายการในบันทึกการใช้งานที่เกิดจากการทดสอบ
- ระบบอีเมลยืนยัน (ดูรหัสผ่าน / ลืมรหัสผ่าน) ทดสอบด้วยอีเมลจริง ได้รับเลขยืนยันจริง

## 6. ข้อจำกัดที่ต้องรู้ (พูดตามจริง)

1. **ข้อที่ยังไม่ผ่าน 1 ข้อ** — เทสต์ตรวจการรวมลูกค้าชื่อซ้ำ ตกเฉพาะตอนรันหลายชุดพร้อมกัน เพราะชุดอื่นเพิ่ม/ลบลูกค้าชื่อเดียวกันคั่นกลาง รันเดี่ยวผ่านทุกครั้ง — เป็นข้อจำกัดของสภาพการทดสอบ ไม่ใช่ของระบบ
2. **ด่านจำกัดคำขอเลือก "ปล่อยผ่าน" เมื่อฐานข้อมูลตอบไม่ทัน** — ตั้งใจให้คนทำงานใช้งานต่อได้ตอนระบบสะดุด แลกกับว่าการยิงถล่มหนักมากพร้อมกันอาจหลุดด่านบางส่วน เปลี่ยนเป็นปฏิเสธไว้ก่อนได้ถ้าต้องการ
3. **ยังไม่มีข้อมูลจริงในระบบ** — ฐานข้อมูลจริงยังว่าง ต้องนำเข้ารายชื่อตัวแทน แคตตาล็อกสินค้า และราคากลางก่อนเปิดใช้
4. **เว็บตัวอย่าง (demo) ไม่ต่อฐานข้อมูล** — เป็นเจตนา ให้ผู้ชมลองกดเล่นได้โดยไม่กระทบข้อมูลจริง รีเฟรชแล้วกลับเป็นค่าเริ่มต้น

## 7. วิธีรันชุดทดสอบเอง

```
npm run test:unit     # เทสต์ย่อย 317 ข้อ (ไม่ต้องเปิดเซิร์ฟเวอร์)
npm run checks        # ชุดกันพลาด 11 ตัว
npm run typecheck     # ตรวจชนิดข้อมูลทั้งโปรเจกต์
npx playwright test   # ชุดเต็มเสมือนผู้ใช้จริง (ต้องเปิดฐานในเครื่องก่อน: npx supabase start)
```

ชุดเต็มใช้เวลาประมาณ 11-12 นาที รันบนฐานข้อมูลในเครื่อง (Docker) ไม่แตะข้อมูลจริง
