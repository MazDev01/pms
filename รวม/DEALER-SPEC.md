# Benjamin PMS — Dealer Workspace (โมดูล + ฟังก์ชัน)

> เอกสารนี้สกัดจากซอร์สโค้ดจริง ไม่ใช่จากเอกสารออกแบบ · ระบุเฉพาะสิ่งที่โค้ดทำจริง

## บริบทระบบ

**Benjamin PMS** = Sales CRM ของบริษัทขาย **อาคารสำเร็จรูป/โครงสร้างเหล็ก (PEB)**
Stack: Next.js 15 App Router + React 19 + TypeScript · ตอนนี้เป็น **frontend-only** ข้อมูลอยู่ใน mock + localStorage (ยังไม่มี backend)

มี 2 พื้นที่ทำงาน:
- **HQ (สำนักงานใหญ่)** — เจ้าของข้อมูลกลาง: แคตตาล็อกแม่แบบ, ราคากลาง, เป้าหมาย, นโยบาย, บัญชีตัวแทน
- **Dealer (ตัวแทนจำหน่าย)** — คนขายจริง ← **เอกสารนี้ว่าด้วยฝั่งนี้เท่านั้น**

**ขอบเขต: งานขายล้วน (Sales-only)** วงจรชีวิตจบที่ ปิดการขายได้/ไม่ได้
**ไม่มี**และห้ามมี: ก่อสร้าง · ผลิต · ติดตั้ง · วิศวกรรม · ซ่อมบำรุง · ERP · บัญชี · SLA

## วงจรธุรกิจหลัก

```
ลูกค้าเป้าหมาย (Lead) ──ติ๊กงานทีละขั้น──> เสนอราคา ──> ปิดการขาย (WON)
                                                            │
                                                            └──> สร้าง "ลูกค้า" อัตโนมัติ
                                                                 (สร้างตรงไม่ได้)
```

**7 สถานะของลีด** (เลื่อนอัตโนมัติจากการติ๊ก Checklist ไม่ใช่เลือกเอง):
`WAITING` ติดต่อแล้ว → `BULLET` รวบรวมความต้องการ → `QUOTED` เสนอราคา → `FOLLOWUP` ติดตามผล → `NEGO` เจรจาต่อรอง → `PAID` ปิดการขายสำเร็จ / `CANCELLED` ปิดการขายไม่สำเร็จ

**5 สถานะใบเสนอราคา:** `draft` ร่าง → `sent_to_client` ส่งแล้ว → `won` ตอบรับ / `lost` ปฏิเสธ / `expired` หมดอายุ
(`lost`/`expired` เปิดร่างใหม่ได้ · `won` คือปลายทาง)

## โมดูล

### 1. `/dashboard` · แดชบอร์ด
**อ่านอย่างเดียว ไม่มีการเขียนข้อมูลเลย**
- KPI 5 ตัว: เป้าหมายทั้งปี + %สำเร็จ, มูลค่าโอกาสเปิด, ลีดวันนี้, งานติดตามวันนี้, อัตราปิดการขาย
- กราฟ: ยอดขายรายเดือนเทียบเป้า · ลีดเทียบใบเสนอราคา · โดนัทสถานะดีล
- อันดับผลงานผู้รับผิดชอบ · ยอดขายตามสินค้า
- งานที่ต้องทำวันนี้ · ลีดค้างเกิน 7 วัน · ใบเสนอราคาล่าสุด · ดีลมูลค่าสูงสุด · ไทม์ไลน์กิจกรรม
- กรองช่วงเวลา

### 2. `/leads` · ลูกค้าเป้าหมาย ← โมดูลหลักของระบบ
**รายการ**
- ค้นหา · กรอง (สถานะ, ผู้รับผิดชอบ, จังหวัด, แหล่งที่มา, ช่วงมูลค่า, ขาดติดต่อ 7/14/30 วัน) · เรียง · แบ่งหน้า
- สลับ ตาราง ↔ Kanban · **ลากการ์ดข้ามคอลัมน์ = เปลี่ยนสถานะ**
- เปลี่ยนสถานะ inline · **แก้มูลค่า inline** · ลบ (มี confirm)

**สร้าง**
- เพิ่มลีด: บริษัท, ผู้ติดต่อ, โทร, อีเมล, จังหวัด, แม่แบบที่สนใจ, มูลค่าประเมิน, **พื้นที่ (ตร.ม.)**, ขั้นตอน, แหล่งที่มา, ผู้รับผิดชอบ, หมายเหตุ, โลโก้
- ระบบออกเลข `#L-xxxxx` + **สร้างรายงานติดตาม + Checklist งานอัตโนมัติ**

**แผงรายละเอียด (4 แท็บ)**
- **ภาพรวม** — แก้ข้อมูลในที่เดิม (ไม่เด้ง popup)
- **งาน** — ติ๊ก Checklist → **เลื่อนสถานะอัตโนมัติ** · บันทึกว่าใครติ๊กเมื่อไหร่ · **บังคับลำดับ** (ข้ามขั้นไม่ได้ / ถอยไม่ได้ถ้าขั้นถัดไปติ๊กแล้ว)
- **ใบเสนอราคา** — สร้าง / แก้ / ทำสำเนา / ส่ง / ลบ / พิมพ์ PDF · **BOQ ตั้งต้นอัตโนมัติ**: จำนวน = พื้นที่ของลีด (ไม่มี → มูลค่าประเมิน ÷ ราคากลาง), ราคา/หน่วย = ราคากลาง HQ
- **ไทม์ไลน์** — ดูกิจกรรม · เพิ่มนัดหมาย (ไหลไปปฏิทิน) · แนบไฟล์ (ไหลไปคลังไฟล์) · แก้รายงานติดตาม

**ปิดการขาย**
- Won → ติ๊กงานครบ + `PAID` → **สร้างลูกค้าอัตโนมัติ** + ผูกใบเสนอราคาที่ออกก่อนหน้าเข้าลูกค้าใหม่ย้อนหลัง
- Lost → เลือกเหตุผลจากรายการที่ HQ กำหนด

### 3. `/quotations` · ใบเสนอราคา
**ทะเบียนใบทั้งหมด — สร้างใหม่ที่นี่ไม่ได้ ต้องออกจากหน้าลีด**
- ค้นหา · กรองสถานะ/ช่วงเวลา/จังหวัด · เรียง · แบ่งหน้า · สลับ รายการ↔การ์ด · ส่งออก CSV/PDF
- แก้ไขใบ: ลูกค้า (prefill จังหวัด/ประเภท/ชื่อโครงการ/ผู้รับผิดชอบ), BOQ, สถานะ, วันที่, วันหมดอายุ
- **แก้ผู้รับผิดชอบ → เขียนกลับต้นทาง** (ปิดการขายแล้ว→เขียนที่ลูกค้า · ยังเป็นลีด→เขียนที่ลีด)
- เปลี่ยนสถานะตาม workflow · ส่งอีกครั้ง · **พิมพ์ A4** (ใบเก่าใช้สแนปช็อตชื่อบริษัทตอนออก) · ลบ
- คำนวณเอง: ยอดรวมย่อย = Σ(จำนวน×ราคา/หน่วย) · VAT จากนโยบาย HQ · วันหมดอายุ = วันที่สร้าง + อายุใบ

**คอลัมน์ตาราง:** เลขที่ · ลูกค้า · โครงการ · ประเภท · ผู้รับผิดชอบ · มูลค่า · สถานะ · วันที่สร้าง · หมดอายุ

### 4. `/customers` · ลูกค้า
- ค้นหา · กรองสถานะ/ประเภทลูกค้า · เรียง · แบ่งหน้า · ส่งออก · พิมพ์ข้อมูลรายราย

## ข้อจำกัดของ Dealer (บังคับจริงในโค้ด)

1. แคตตาล็อกแม่แบบ + ราคากลาง = **อ่านอย่างเดียว** (HQ แก้ที่ `/hq/master`)
2. **VAT ตั้งเองไม่ได้** — อ่านจากนโยบาย HQ
3. อีเมลเข้าสู่ระบบ + รหัสผ่าน = HQ คุม
4. เป้าหมายยอดขาย = HQ ตั้ง
5. **สร้างลูกค้าตรงไม่ได้** — เกิดจากปิดการขายเท่านั้น (ยกเว้นนำเข้าลูกค้าเดิม ซึ่งถูกตีตรา `imported`)
6. **ออกใบเสนอราคาจากหน้า /quotations ไม่ได้** — ต้องออกจากลีด
7. เลขที่ใบเสนอราคาแก้รายใบไม่ได้
8. ประเภทอาคารในใบ = ดึงจาก BOQ แถวแรก แก้เองไม่ได้
9. ติ๊กงานข้ามลำดับไม่ได้ / ปรับ % ความคืบหน้าเองไม่ได้
10. พิมพ์ใบไม่ได้ถ้ายังไม่ตั้งชื่อบริษัทผู้ออก
11. ลีดที่ปิดการขายแล้วหายจาก `/leads` ไปอยู่ `/customers`
12. แท็บใบเสนอราคาในหน้าลูกค้า = อ่านอย่างเดียว

## หนี้ทางเทคนิคที่ต้องรู้ (ยังไม่แก้)

1. **UI บอกไม่ตรงโค้ด** — ป้าย "เลขที่ใบ สำนักงานใหญ่กำหนด" แต่จริง ๆ ค่าของตัวแทนชนะ HQ และหน้าตั้งค่าให้แก้ได้เต็ม · อายุใบก็เหมือนกัน
2. **ไม่มีการบังคับสิทธิ์ระดับ route** — เช็กแค่ล็อกอินหรือยัง ไม่เช็ก HQ/Dealer · เมนูแค่ซ่อน · สลับ role ได้อิสระ → ไม่ใช่ security boundary
3. **ไม่กรองข้อมูลตามรหัสตัวแทน** — ทุกหน้าใช้ข้อมูลชุดเดียว (ตอนนี้มีตัวแทนเดียว) พอมีหลายตัวแทนจะเห็นข้อมูลข้ามกัน
4. **ข้อมูลไม่ persist** — ลีด/ใบเสนอราคา/ลูกค้า อยู่ใน React state เฉย ๆ **กด F5 แล้วหายกลับเป็นค่าตั้งต้น** (มีแค่ตั้งค่า/ไฟล์/โปรไฟล์ที่ลง localStorage จริง)
5. **โค้ดตาย** — ระบบ "ดีล" แยก (`addDeal`/`moveDealStage`/`closeDeal`) ไม่มีหน้าไหนเรียก เพราะยุบเข้า Kanban ลีดแล้ว
6. **ยังไม่มี backend** — ทั้งหมดเป็น mock ในเครื่อง
